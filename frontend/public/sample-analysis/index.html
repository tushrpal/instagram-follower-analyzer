Methodology

  1. Read the follower and following JSON records included in the selected ZIP.
  2. Normalise usernames for comparison and remove duplicate records within a set.
  3. Apply set intersection and difference formulas for current relationships.
  4. For change analysis, compare two dated follower sets in chronological order.
  5. Present the categories and counts for review; do not infer motives or engagement from a relationship alone.

Limitations to understand

Snapshot, not event log. A difference shows that a username left a set between dates; it does not explain why.

Input-dependent. Missing files, export options, format changes, and incomplete data can affect results.

Account changes. Deletion, deactivation, or username changes may look like a lost account in a simple set comparison.

No engagement score. Following relationships do not reveal reach, views, saves, or the quality of a connection.

No historical reconstruction. The tracker cannot determine past followers unless an older snapshot is available.

Review before acting. Treat lists as analytical aids, not proof of intent or a reason for automated decisions.

Privacy and storage in the real tracker

Guest analysis

The ZIP is parsed in your browser and the result stays in sessionStorage. A guest result is not uploaded and normally disappears when that browser session ends.

Optional saved history

A signed-in user may explicitly save derived usernames, profile details, categories, counts, relationships, and timestamps. The raw ZIP is not uploaded. Saved history remains until the session or account is deleted.

A separate optional OAuth connection applies only to eligible Instagram professional-account features, not ZIP analysis. See the Privacy Policy for analytics, advertising, email, logs, and other service details.
